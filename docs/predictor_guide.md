# 链路风险预测器：训练与评估指南

> 目标：**给定过去 2 秒的链路指标，预测未来 1 秒会不会变差**——这是一个普通的监督学习二分类问题，不需要深度强化学习，也不需要 GPU。
> 代码：`ml/make_demo_traces.py`（造演示数据）、`ml/build_dataset.py`（滑窗造样本）、`ml/train_predictor.py`（训练+评估+出图）。
> 本文所有数字都来自**合成演示数据**，只用来验证流程与代码，**不能当实验证据**；真数据请用探针采。

## 二、先定标签（这一步比选模型重要 10 倍）

| 项 | 取值 | 说明 |
|---|---|---|
| 特征窗口 W | **2.0 s**（过去） | 只用过去，绝不能用未来 |
| 预测窗口 H | **1.0 s**（未来） | 标签只看这一段 |
| 滑窗步长 S | **0.2 s** | 采样密度 |
| 恶化判据 | 未来 H 内 **RTT P95 ≥ 80 ms** 或 **丢包率 ≥ 3%** | 两个条件任一成立 → `label=1` |

```python
# ml/build_dataset.py 的核心逻辑（简化）
past   = slice(i - w + 1, i + 1)      # 过去 2 s
future = slice(i + 1, i + 1 + h)      # 未来 1 s
label  = (p95(rtt[future]) >= 80) or (mean(lost[future]) >= 0.03)
```

**为什么是 1 秒**：调度窗口是 100–500 ms，预测太远没有意义（文献里 WiFi 链路可预测时域约 1–2 s）；1 s 的提前量足够让调度器在下一帧降级。
**阈值怎么定**：`80 ms` 和 `3%` 是"业务上算差"的口径，不是数据里算出来的——写在报告里，不要事后按结果调。

## 三、特征（13 个，全部来自过去窗口）

| 类别 | 特征 | 直觉 |
|---|---|---|
| RTT | `rtt_med`、`rtt_p95`、`rtt_std`、`rtt_min`、`rtt_max`、`rtt_slope`、`rtt_delta` | 现在多慢、波动多大、在变好还是变坏 |
| 丢包 | `loss_rate`、`jitter_med` | 是否已经在丢、是否在抖 |
| 信号 | `rssi_med`、`rssi_std`、`rssi_slope` | 信号强度与趋势（遮挡/走远最先体现在这里） |
| 质量 | `valid_ratio` | 窗口里有多少有效采样（丢包太多时降权） |

**不要加的**：位置标签（部署时不一定知道）、未来任何统计量、被标签定义用到的同一个阈值再当特征（会造成循环论证）。

## 四、评估：两种划分都要跑，且必须打败两个基线

### 4.1 划分方式

| 划分 | 做法 | 回答什么问题 |
|---|---|---|
| `--split time` | 每条 trace 前 70% 训练、后 30% 测试（中间留 1.2 s gap 防重叠泄漏） | 同场景下往后预测准不准 |
| `--split trace` | 留一条 trace 完全不参与训练，用它测试（LOTO） | **换一个场景还能不能用**（更重要） |

### 4.2 基线（不训练，必须比过它们才有意义）

- `persistence`：当前 RTT P95 已经超阈值 → 判 1（"已经坏了才说坏"，没有提前量）；
- `rule`：`rtt_med > 0.8×阈值` 或 `loss_rate > 0.5×阈值` → 判 1（人工阈值法）。

### 4.3 指标

| 指标 | 用法 |
|---|---|
`AUC` / `PR-AUC` | 排序能力（类别不平衡时 PR-AUC 更可信） |
`F1` / `Recall@FPR≤10%` | 在可接受误报下的检出能力 |
**误报率 / 分钟** | 在"全程良好"的 trace 上，每分钟误报几次——**调度最怕这个** |
**预测提前量** | 事件发生前多少秒第一次报警（中位数/P90） |

## 五、演示数据上的结果（合成数据，仅验证流程）

**事件 trace（degrade / oscillate，LOTO 划分平均）**

| 模型 | AUC | F1 | Recall |
|---|---|---|---|
| persistence（不训练） | 0.945 | 0.702 | 0.552 |
| rule（不训练） | 0.890 | 0.843 | 0.861 |
| 逻辑回归 | **0.958** | **0.919** | 0.901 |
| 梯度提升（HGB） | 0.938 | 0.886 | 0.912 |

**全程良好的 trace 上的误报率**

| 模型 | 误报 / 分钟 |
|---|---|
| rule | 1.41 ~ 1.62 |
| 逻辑回归 | **0.00** |
| HGB | 0.00 ~ 0.20 |

**提前量**：中位数 **4.8 s**，P90 5.0 s（73 个事件；上限 5 s 是评估窗限制）。

> 结论（在合成数据上）：训练模型在**同样召回**下把误报从 1.5 次/分钟压到 0，这才是"预测"的价值——**不是比谁 AUC 高，而是比谁在不出假警报的前提下更早发现**。

## 六、接进项目（这一步才是交付）

1. **日志加字段**（契约 v0.2）：`pred_p_degrade`（0–1）、`pred_risk`（0/1/2：低/中/高）、`pred_model_hash`（模型版本，便于复现）。
2. **风险分级**：`p ≥ 0.7 → 高`、`0.4 ≤ p < 0.7 → 中`、`p < 0.4 → 低`（阈值在验证集上定）。
3. **调度器用滞回**：高→降档；回落到"低"并持续 2 s 才升档（防抖，对应动作契约里的 `exec_switched`）。
4. **推理开销**：sklearn 模型在树莓派 5 上 `predict_proba` 单次 < 1 ms，可以直接进 100 ms 控制循环。
5. **模型随日志走**：每次实验记录 `pred_model_hash`，否则"复现"会被质疑。

## 七、踩坑清单（按血泪程度排序）

| 坑 | 表现 | 正确做法 |
|---|---|---|
| **随机打乱划分** | 指标好得离谱 | 时间序列必须按时间块划分；跨场景用 LOTO |
| **训练/测试重叠** | 窗口重叠导致信息泄漏 | 时间划分留 gap（≥ 预测窗口） |
| **只在测试集上选阈值** | 过拟合阈值 | 用训练集 5 折 OOF 概率选阈值（脚本已实现） |
| **只有"坏链路"数据** | 模型在好链路上乱报警（本仓库 `--split time` 就复现了这个：12.98 次/分钟） | 采集时**必须**采 2–3 条"全程良好"的 trace；或用概率校准 |
| **类别不平衡** | 全判"不恶化"也有 70% 准确率 | 看 PR-AUC / F1 / 误报率，不看 accuracy |
| **用未来统计量当特征** | 离线指标爆表，上线就崩 | 特征窗口严格在标签窗口之前 |
| **NaN 处理不一致** | 训练用中位数、测试用 0 | 训练集中位数，测试集复用（脚本已实现） |
| **忽略 RSSI** | 减少 1–2 秒提前量 | 遮挡/走远最先体现在 RSSI，务必带上 |

## 八、真数据要采多少

| 场景 | 条数 | 每条时长 | 作用 |
|---|---|---|---|
| 全程良好（桌边） | 2–3 | 5–10 min | 负样本 + 误报评估 |
| 走动/遮挡（隔墙、人多） | 3–4 | 5–10 min | 主要正样本来源 |
| 中断/重连（走远再回来） | 2 | 3–5 min | 极端事件 |
| 合计 | **8–10 条** | 40–60 min | 约 5–7 万包、2–3 万个滑窗样本 |

采集时**主动制造事件**：走到遮挡处、开门关门、走远再回来；否则负样本太多，模型学不到"变差前长什么样"。
