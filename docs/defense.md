# 答辩口径：创新点、卖点与问答

> 用途：评委/导师问"你们和传统方案比有什么创新"时，照着说。
> 原则：**不吹首创，只讲可验证的差异**；每个卖点后面必须跟一个能当场指给他看的证据（图/数/装置）。

---

## 一、一句话卖点（按对象选一句）

| 对象 | 一句话 |
|---|---|
| **评委** | 我们把"通信约束"从一句口号，做成了**50 块钱的 ESP32 可控弱网实验台 + 可复现的对照证据**。 |
| **导师** | 我们不是做更准的检测模型，而是做"链路恶化前先降级"的决策闭环，并用固定基线和跨场景验证证明它有效。 |
| **同学/观众** | 网络一差巡检就瞎，我们的系统会**提前知道自己要不行了，先调动作**，而不是卡了再救。 |

---

## 二、先定义"传统方案"（不定义清楚，创新就无从谈起）

| 传统做法 | 具体是什么 | 它的问题 |
|---|---|---|
| **T1 固定配置** | 固定分辨率/帧率，卡了才重传 | 冗余流量高、时延尖峰大，最笨的基线（我们的 `B0`） |
| **T2 反应式阈值** | RSSI/丢包低于阈值才降级 | 已经掉下去了才动作，掉的那一下必然丢帧/超时（我们的 `B1`/`rule` 基线） |
| **T3 纯仿真研究** | ns-3/trace-driven 仿真 | 没有实物、参数自己设，评审无法复核（"数据哪来的"） |
| **T4 可视化大屏** | 跑个模型 + 画一堆图 | 面板只是装饰，不参与决策，无法回答"为什么这一刻这么做" |
| **T5 端或云单点** | 全上传云，或全在端侧 | 不考虑链路状态与算力约束，链路一差就崩 |

**我们的定位**：T1/T2 的"反应式"→ 换成**预测前馈**；T3 的"仿真"→ 换成**实测+可控注入**；T4 的"展示"→ 换成**闭环决策解释**。

## 三、创新点分三层（答辩就按这三层讲）

### 第 1 层：装置创新——把"弱网"变成可复现的实验条件（最硬的差异）

- 一块 **ESP32-S3（约 50 元）** 同时做三件事：**20 Hz UDP 四时间戳探针**（亚毫秒级 RTT 测量）、**可控打流**、**RSSI/信道上报**；
- 配合 Clumsy 注入延迟/丢包/抖动，能造出**任意可复现**的链路条件；
- **对比**：5G 专网试验台是百万级、不可及；纯仿真是"自己造数据"。
- **一句话**：别人要么"没有真链路"，要么"没法复现"，我们两个都解决了，成本 50 块。
- **证据**：`docs/probe_guide.md`、`firmware/esp32s3_probe/`、探针实测 RTT/RSSI 曲线。

### 第 2 层：方法创新——从"反应式降级"到"预测前馈 + 约束感知调权"

- **预测前馈**：过去 2 s 的 RTT/RSSI/丢包 → 预测未来 1 s 是否恶化（二分类），**提前一个调度窗口**动作；
- **约束感知**（视觉侧接入后）：把时延/带宽写成 CMDP 约束，用对偶变量在线调权，权重不是手调而是"约束的价格"；
- **消融可证**：去掉预测 = 退化成 T2；保留预测 = 提前量 + 误报下降。
- **一句话**：不是把阈值调得更细，而是**把决策提前到恶化发生之前**。
- **证据**：预测器的 AUC/提前量/误报率（模型 vs `rule` 基线），消融表。

### 第 3 层：工程与证据创新——可复核的闭环

- **统一时间线日志 + 字段契约 + 校验脚本 + CI**：任何人 clone 下来能跑出同样的数字；
- **面板不是装饰**：每条决策带 `why`，能回答"这一帧慢在哪、为什么降级、奖励谁在主导"；
- **诚实边界**：实测 trace、LOTO 跨场景、主动写局限（单场景/轻量模型/无真实 5G）。
- **一句话**：我们的成果是**可复核的证据**，不是"看起来厉害"的 demo。

> 如果只能记三个词：**可复现（装置）→ 提前量（方法）→ 可复核（证据）**。

## 六、必问的 8 个问题与答法

**Q1「这不就是用阈值降级吗？」**
> 阈值是反应式的：等指标掉下去才动作，掉的瞬间必然丢帧。我们做的是"预测未来 1 s"，在同一召回下把误报从每分钟 __ 次降到 __ 次，并且提前 __ 秒动作——这是基线 `rule` 做不到的（现场翻到对比页）。

**Q2「预测不准怎么办？」**
> 三层兜底：① 滞回（升档要持续 2 s 才生效，防抖）；② 预测低置信时退回阈值规则；③ 误报的代价可量化（切换频次、流量），我们在指标里单独统计。预测是"加分项"，不是"单点依赖"。

**Q3「和自适应码率（ABR）有什么区别？」**
> ABR 是应用层、靠缓冲区水位、无端侧算力与端/边切换；我们是"感知+计算+传输"联合决策，链路预测是独立可测模块，还带端侧/边缘两种推理位置。ABR 的 MPC 思路我们当基线引用，不重复造轮子。

**Q4「为什么不用强化学习？」**
> 我们评估过：RL 需要可信的仿真环境 + 大量交互，10 周内很难证明它比规则好，且不可解释、不可复现。所以我们用"规则 + 一步前瞻"，把 RL 作为可选对照；如果数据显示 RL 更好，我们再上——目前证据不支持。

**Q5「数据是不是你们自己编的？」**
> 训练和测试全部来自 ESP32 实测 trace，每条带距离/遮挡/信道/注入参数（`manifest.csv`），合成数据只用于跑通代码，且面板上明确标注。测试集用"留一条 trace 不训练"来防泄漏。

**Q6「创新性不够强？」**
> 我们没打算在"模型新颖度"上竞争——这个赛道更看重成果完成度和证据质量。我们的创新在三处：装置（弱网可复现）、方法（预测前馈）、证据（可复核闭环）。任何一条都能当场演示，不是 PPT 上的概念。

**Q7「实际价值在哪？」**
> ① 50 元装置可复制到任何实验室；② 调度逻辑可迁移到巡检/遥操作/AGV/路侧感知；③ 我们给出的是"小规模可复现基线"，后续接真实专网或更大模型时可直接复用。

**Q8「就你们两个大二，能做完吗？」**
> 我们已经交付了：字段契约（47 字段 + 校验 + CI）、ESP32 探针固件（编译通过、已实测）、预测器（训练/评估/出图）、可视化面板（三页签、CI 冒烟）。剩下的工作量集中在采数据和联调——按 8 周计划推进，每个里程碑都有可演示物。

## 七、三条不要说的话

1. ❌ 不说"**首创/国内外首次**"——没有查新，说了就被抓；
2. ❌ 不说"**真实 5G / URLLC 专网**"——我们是"类 URLLC 约束 + WiFi 实测"；
3. ❌ 不说"**我们的检测模型更准**"——检测是黑箱，我们不训练、不比 mAP。

## 八、答辩前必须补的一个实验（半天）

**消融：同一批实测 trace 上跑三组**
1. `rule`（当前指标超阈值才降）——传统方案；
2. `pred`（只加预测，不加滞回）——证明预测的贡献；
3. `pred + 滞回`（完整方案）——证明稳定性的贡献。

产出：一张三组的"提前量 vs 误报率"散点图。**这张图就是"创新点"的物证**，比任何形容词都有效。
